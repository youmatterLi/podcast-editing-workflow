# 播客剪辑工作流

一套面向访谈播客的剪辑方法参考，适合「AI 动手剪、人来听看定稿」的分工。AI 听不到声音，所以凡是听感上的判断都要有**量出来的证据**；量不了的如实写「没查」。最终听看和编辑取舍由主持人（或其他约定的批准人）完成。

本文件只写方法和验收目标，不绑定任何工具；文中提到的工具名都只是一种可选实现。文中的数字除特别说明的交付规格外，都是**示例，可按你的节目调整**。

适用三类产物：

| 产物 | 执行深度 | 审片重点 |
| --- | --- | --- |
| 整集播客 | 五个阶段完整执行；内容结构、多轨同步、隐私、全部接点 | 完整听看候选整集，重点复核删减与重排 |
| 中长视频（单主题） | 五个阶段精简执行；保留必要背景、技术检测、字幕 | 完整看片，重点复核删减、字幕 |
| 短视频切片 | 只做必要动作；三项核心检查：隐私、原意、接点 | 整条完整听看 |

**五个阶段**（全文统一用这五个名字）：准备 → 定位 → 剪辑 → 后期 → 交付。

**纯音频作品**不适用：画面相关的一切（机位、帧数对齐里的画面侧、抽帧、进度条画面、字幕烧录、安全区、水印、封面、结束图）。章节标记、响度、刀口、语义、音乐仍然适用。不适用的项在检查记录里写「不适用＋原因」。

参考文件，用到时再读：

- `references/刀口与删结巴.md`：两类剪切（普通剪切、连读微剪）怎么定、怎么验；删结巴的剪／不剪
- `references/声音处理.md`：按实际情况决定处理链、响度、多人音量
- `references/整集包装.md`：钩子、章节、进度条、音乐、字幕、名牌、水印（多为示例设置）
- `references/全片检查清单.md`：交付前逐条核的清单，含适用范围

## 一、贯穿全程的原则

1. **一条做完再做下一条。** 排队的几条片子是队列，不是同时开工。并行对审片的人是负担——每条都只看到半截。
2. **事先约定谁批准什么。** 开工前说清：内容取舍谁定、听感谁确认、哪些技术处理（转码、换分辨率、统一响度）只需按约定复核、发布谁批。
3. **沉默不算批准。** 只回「收到」「稍后看」、或没回的，都不算确认。确认要记下范围：是哪个版本、哪个方面（声音／语义／画面／文字）、批准人的原话。声音确认了不代表语义也通过。
4. **实质删改要重新确认。** 已确认的内容、切点、镜头安排、标题文字，后续修改不去碰；确实要改的，记原因，送批准人重新确认。只换分辨率、转码这类不改内容的处理，按事先约定的方式复核即可，但要按时间映射核对内容没变（见第六节）。
5. **新加的通用规则只管以后**，不回头改已批准发布的作品。
6. **技术通过不等于语义通过**，两样分开查、分开记。
7. **能自己判的自己判**，只把必须批准人定的攒到一次问；每处给一个推荐，不出选择题让人代选。
8. **条件允许时，由未参与制作的人独立复核**再交批准人。复核人只查、只提修改意见，不替做的人改。独立复核是建议，不是交付的前提；没有复核人时，在交付说明里写明「未经独立复核」。
9. **检查本身也会骗人。** 见第六节「教训」。

## 二、准备：看素材、建锚点

### 先看素材怎么录的、质量如何

1. **是不是原始录制**：看文件制作信息（编码、码率、导出时间、软件名）。从相机、录音笔直接拷出来的、录制平台给的每人一条分轨，算原始；进过剪辑软件再导出的、合并过的、压缩过的，不算。
2. **有没有更原始的那一份**：在线录制看有没有每人一条的声音和各机位画面；相机录的看有没有另外的录音笔或外接麦。有就取原始的。
3. **声音和画面本身的质量**：采样率、码率、高频有没有内容、底噪多大、有没有削顶失真、整条响度；画面看实际分辨率和码率。

查完写进本期素材记录。只拿得到压缩件的，先告诉批准人「能拿到的最好素材是什么、差在哪」，同意再做。中途换了底子，受影响的片段全部重出，交付说明里写明。

### 选对源

- 整集或首次独立视频：用原始素材。
- 短视频、衍生切片：用**已批准的发布版**（已落实所有必删内容）；横版有水印的话用它的无水印母版。不要用原始录音做切片源，以免带回已删内容。
- 转写稿必须和它所配的那个文件对应，原片的转写不能配发布版。

### 其余准备

- **核对素材**：时长、分辨率、帧率、音轨、采样率、旋转信息、解码错误。
- **多机位**：按真实身份和音源核对机位，不凭文件顺序猜；用共同声音事件或波形对齐，分别记各段偏移，查开头、中段、结尾的漂移。
- **在线录制**：先盘点实际拿到的独立轨、合成画面，不假设齐全；只有合成画面就按现有构图剪。
- **单人视频**：直播查等待段、屏幕通知和用户名隐私；手机查旋转和变帧率；相机查分段和外接录音。
- **声音处理放在最前面**（见 `references/声音处理.md`），转写和剪辑都用处理后的音频。
- **转写**（词级）：长素材先抽音频再切块，**按每块实际起止时间恢复源时间**，不按「块序号 × 块长」推算；块边界前后检查有没有被截断的句子，有就取跨边界窗口重转。中间产物放在你的工作目录，不放系统临时目录。
- **合并**：块边界去重；固定段号后不再重编号；改错字保留原始转写和修改记录。

**每期记录的最小内容**：本期用途；素材（录法、原始文件、质量）；必删、必保留内容；敏感话题的同义说法（供搜索）；嘉宾授权与公开边界；已确认的特殊剪辑决定（能对上位置的写源时间）。

## 三、定位：把建议和反馈变成剪辑范围

- 先读本期必删、必保留和公开边界，再读最新反馈。源锚点不随文字修改漂移。
- 反馈分成「删声音」「只改字幕」「保留」「重排」「待讨论」。文字润色不自动触发删音频；标注不明确的保留原样、列待审。
- 用**首句加尾句**共同定位；重复句结合上下文、说话人和源时间消歧。不凭一处文本命中就删。

**定稿载体（工具自选）**：整集用**批注稿**——整期一字不落的全文稿，你建议删的标出来，批准人在上面直接改（删、恢复、加删）。它比勾选候选清单好：批准人能提出你没想到的删改。短视频可以用同样的批注稿，或一张**剪辑决定表**（每行一句：保留／删除／改字幕）。无论哪种，都要满足：

- 读回规则简单不歧义（例如「有标记＝删，无标记＝留」，不靠颜色区分含义）；
- 每一句能还原到源时间，只标半句也能还原；
- 每个读回的删除点再按刀口规则落到可剪的位置；找不到合适位置的不硬切，往外让，并说明让了多少。

每出一版，可以重出一份按实际删除标好的批注稿给批准人核对。删了哪些字，以**成片重新转写和源转写的对齐**作为主要线索，再到可疑处回听确认；词级时间戳偏差可能很大，不单独拿它定删留。嘉宾要求删除的原文不放进共享稿，只放占位。

**质量门**：每个执行范围可回查源位置、首尾句、动作、理由。有歧义的范围不自动删。

## 四、剪辑：按已采纳的决定生成候选片

**先固定决定**：保存检查点；合并同一源上的重叠删除；检查必保留范围和问答依赖。删除同时作用于所有音轨和所有机位；字幕按同一时间映射重建；交叉淡化和补画面不得带回已删素材。

### 时间映射（统一定义）

对每个保留段 i，分开记三样：

- **源入点** `in[i]`、**源出点** `out[i]`：在源素材上的起止，单位精确到采样点；有画面时吸附到帧边界 `round(t×fps)/fps`。
- **段长** `len[i] = out[i] − in[i]`（不是相邻两段入点之差——中间可能隔着删除区间）。
- **输出起点** `start[0] = 0`，`start[i] = start[i−1] + len[i−1] − overlap[i]`，其中 `overlap[i]` 是这个接缝的交叉淡化长度（硬切为 0）。

重叠量的约束：

- `overlap[i]` 不超过相邻两段各自的可用长度（`overlap[i] ≤ min(len[i−1], len[i])`），否则会吃掉整段。
- 有画面时，`overlap[i]` 要能落到整数帧；落不到整帧的，写明不足一帧的余量怎么处理（例如声音侧取整到帧，或把余量计入下一段的入点），并让声音和画面用同一种处理。
- 重叠区只能用保留范围内的素材：淡入淡出不得越出 `in[i]`／`out[i]`，不得带回必删内容。需要额外素材做淡接时，从保留范围内部取，而不是向外延伸。

规则：

1. **一律算到帧／采样点，不按秒取整**，画面长度按帧数给。逐段舍入会累积成肉眼可见的声画漂移。
2. **声音和画面用同一张映射表。** 声音做交叉淡化重叠时，画面要按同样的 `overlap` 处理（重叠、或在同一位置等量裁掉），保证两侧的 `start[i]` 一致。只改一侧就会累积错位。
3. **每次渲染后比对音视频总长**，差超过 1 帧就停下查。数画面真实帧数，和音频采样数换算后比。
4. **每道音频处理跑完做覆盖检查**：片头、片尾、每个接缝两侧都要在处理范围内；**分段量**，不要整条量成一个平均数。
5. 修改过程中只出小尺寸预览；内容定了再出一次最高清，并核对它和预览的保留段表、章节表一致。
6. 给人听看的文件每次只给一个路径，旧版移走归档，文件名带版本号和时间。
7. 日志和记录里的时间统一时区并标明。

### 删结巴、口水话、主持人的重复

发布版里主持人和嘉宾的都删；给嘉宾审阅的版本不删（只删嘉宾要求删的和开头调试、中途打断这类杂乱部分）。目的：**听着顺、不奇怪、切口干净、意思一点不变**。细则见 `references/刀口与删结巴.md`。

- 剪：卡住重起（「我我我」「因因为」）、说半截重说、连接词代词重复、句首当口头禅的「然后」「对吧」。
- 不剪：两句交界碰巧同字、叠字词、应答附和、有意强调的重复、句中当连接的「然后」。
- **主持人同一观点反复说的，精剪到说清一遍**；有意义的重复（总结、强调、换个说法让人听懂）留下。
- 有风险会伤到旁边字的不剪；交付说明里写「扫出几处、剪了几处、几处因风险没剪」。

### 两类剪切

- **普通剪切**（删句、删段、删停顿）：切点落在**真安静处**——按电平找，句尾轻声和气息落到底噪为止；没有真安静处就不在这里切。
- **连读微剪**（删结巴、删连着说的重复字）：本来就没有安静处，只能切在话音里。不套用安静门槛，**每一刀都做技术检查**（重新转写、咔哒声、响度跳变、节奏，作为线索）。人耳可以逐刀听，也可以按事先约定抽听；**抽听不等于每个切点都有人耳确认过**，交付说明里写清实际听了多少刀、共多少刀。

### 删改后上下文连贯

每次删改后查（句内小删也查），范围向前后扩展到能确认关系为止：

- 提问有没有对应回答；回答是否依赖已删的问题或背景。
- 「那些」「刚才说的」「所以」「但是」是否仍有明确指向或前提。
- 人物、事件、时间是否已交代；否定、条件、程度、转述和说话人归属是否保持。
- 删掉例子后是否只剩无依据的结论。
- 跨段拼接有没有制造原访谈没有的因果、认同或观点。
- 修复可以删连接词，但要确认剩下的回答仍回应当前问题。**不为补连接放回必删内容，不合成或编造句子。**

### 多机位与单人

- 完整表达优先用说话人镜头；重叠说话或身份不确定用同一时刻全景。反应镜头只用同一时刻的真实画面；没有合适画面就用诚实的跳切。
- 嘉宾哭、擦鼻子、起身这类不体面的画面换成主持人或两人镜头；换镜头放在句间或停顿处，一处只进一次出一次。
- 单人视频围绕完整句和演示步骤剪，不删掉关键步骤再用字幕补出没发生的动作。

### 接点检查

每个接点取两侧覆盖完整短句的窗口重新转写，和应保留的源段比；有画面的切点前后抽帧；对输出做峰值、响度、静音、黑帧检测。**转写对上只是线索**：听写会漏识别，也会把残字补全，所以对上不能证明字音完整，对不上也要回听确认。不能据此写「衔接自然」或「口型同步」。

多人音量平衡和响度见 `references/声音处理.md`。

## 五、后期：字幕、包装、短视频

### 短视频：先问三个问题

1. **开头**：第一句是一句话的开头吗？还是接在上一句尾巴上？
2. **中间**：自己立得住吗？有没有「为什么」或「怎么做」被留在片外？同一个问题问两遍、同一个意思说两遍的只留一遍；切不开就删整句、换入口或重组。
3. **结尾**：语义完整、结束在该结束的地方即可，不套固定结尾模板。

有一条不对就回源前后各看 40–60 秒，把缺的拉进来。按主题机器切出的候选片两头断在半句是常态，每条都查。**五秒内进主题**，最抓人的话放前面。选题开关在批准人手上：你可以推荐，但开不开工按约定由批准人定。

### 短视频的验收目标（步骤顺序和工具自选）

| 目标 | 验收方法 |
| --- | --- |
| 声音处理在剪之前做完 | 处理覆盖检查（见声音处理） |
| 逐字精简用的是这条片自己的转写 | 用这条片自己的音频重新转写，不从整集稿映射时间 |
| 转写漏掉的字不会被漏删 | 在转写里标成「静音」却实际有明显电平的区间（示例：≥0.3 秒、峰值 > −40 dB）逐个回听；真漏的补进转写 |
| 定稿删掉的确实删掉了、该留的都在 | 至少一道**只回听成片声音**的独立核对（重新转写对定稿，差异逐处回听），不能只做「烧出来的和稿子一致」这类同源比较 |
| 每个切点没砍字 | 拿最终文件对回源逐刀量（见刀口参考）；装封面、改字幕后对最终文件再量 |
| 字幕、竖版裁切、封面、安全区、声画长度正确 | 抽帧加长度比对 |
| 批准人认可 | 按事先约定（通常是整条听看后明确认可） |

不必要的长停顿（示例：同一话题里 ≥0.6 秒）收短，留下的写明为什么。平台限长另做的短版按已认可的长版剪；要不要再送批准人看，按事先约定。

### 字幕、章节、音乐等

细则和示例设置见 `references/整集包装.md`。要点：

- 字幕来自定稿文字，不是转写稿；不改掉声音里真有的字（结巴可只写一遍、「嗯」「啊」可不写）；每次一行，自然断句；交检分「对声音」和「按意思通读」两步。
- 开场钩子 3–5 段，每段单独听得懂；钩子之间的停顿垫现场底噪，不用数字静音。
- 章节按内容推进分大块，起点放在开启话题的提问开头；同一份章节表用于画面进度条、文件章节标记和平台目录。
- 音乐：开场在钩子之后进、正文开口后很快退；片尾垫在最后一段说话底下；开场和片尾用不同的曲子；正文中间默认不放，只在话题大跳处放过渡。
- 任何重新剪辑都要重建字幕、重算章节和进度条。

## 六、交付：用证据交付

### 检查状态

| 状态 | 含义 |
| --- | --- |
| PASS | 实际执行了，证据满足条件（只对该项、该版本成立） |
| FAIL | 违反底线或交付规格；修复重查 |
| REVIEW | 有歧义或取舍，必须人判断；集中提交位置、影响、建议 |
| NOT CHECKED | 本该能做却没做或被工具阻断；写原因 |
| 不适用 | 写原因（例如纯音频作品的画面项） |

每项都写版本，旧版结果不能当新版结果。有 FAIL 或 NOT CHECKED 的版本只能叫「审阅候选」。交付报告把清单每一项都列上状态，不只列做了的。清单见 `references/全片检查清单.md`。

### 送审

- **语义问题**自己判、自己修；判不了的交批准人，给文字：原始上下文、拼接结果（用｜标出切点）、疑点、推荐。不给孤立两句让人猜背景。
- **声音问题**才发音频：注明切点落在哪两个字之间、第几秒；前后留足余量；注明是原声、未混音接口还是最终混音。
- 不送已确认且未受影响的项。减少送审不等于减少自检。
- **新版和上一版比**：比两版保留了源素材的哪几段、按什么顺序；落在已确认范围内的单列并写原因。待听清单只列：新切点、改过的切点、本版新发现的问题。
- 批准人看过一遍完整版之后，新版只列改了哪几处，把要看的地方剪成一条带前后上下文的「重点段」；同时核对没改的地方没变：按两版的时间映射把最终输出的对应区间对齐比对；无损且处理链没变时可以逐采样、逐帧比，有损编码或处理有变化时用合适的容差比对（如声音电平差、画面 PSNR），超出容差的异常区间逐个复核，确认都落在这次改动的范围内。

### 交付内容

成片、必要的字幕，加一份摘要：版本、主要删改、自动检查结果、待审事项、是否经独立复核。没有人听看过就说「自动检查完成，待听看」，不说「已处理好」。修改后只更新受影响范围，重跑相应检查；改过的候选片不继承上一版的批准。

### 教训

- **别拿自己的过滤器验证自己的输出。** 判「跑完没有」要看只有成功／失败才会出现的串，不用正文里到处出现的符号。跑完先不过滤看一次尾部原样输出。看退出码：管道默认只返回最后一个命令的退出码（`cmd | grep | tail; echo $?` 拿到的是 tail 的，通常是 0），开了 `pipefail` 行为又不同；最稳妥的是不接管道，把各命令的输出和退出码分别保存、分别检查（例如 `cmd > out.log 2>&1; rc=$?`）。在 Bash 里也可以用 `${PIPESTATUS[@]}` 取管道里每个命令的退出码（这是 Bash 专用）。**验证用的那条命令，本身也要被验证一次。**
- **基于文稿的检查都是同源比同源**，只能证明「烧出来的和稿子一致」。至少要有一道只回听成片声音的核对。
- **两道检查的盲区不能重叠。** 按时间抽帧会跳过很短的字幕；按内容听写会漏整段漏识别的字。
- **先排除测量假象再下结论**：窗口顶到边界、跨接缝取样、取帧偏一格、源片本身有重复帧，都像真 bug。
- **验证要拿旧版当参照**，新旧同表一起测，一次只改一个变量。
- **改了处理链要重做旧片段**：片头、过场若早于链路改动就作废。
- **声画同步要单独量**：只比「和参照版一致」会漏过参照版本身的错位；用同一机位原声和原画对。
- **试过有效的做法直接用**，不每次做很多版让人挑；对不上已知情况时，先量原因，再出一版样品。
- **整片平均值会掩盖局部问题**：响度、处理覆盖、音量差都分段量。
- **视频帧逐帧读、用完即释放**，不一次载入内存。

# Full Checklist (go through item by item before delivery)

For every item record: status (PASS / FAIL / REVIEW / NOT CHECKED / N/A), version, where the evidence is; N/A and not-done items need a reason. Any FAIL or NOT CHECKED means it can only be called a "review candidate"; any unresolved REVIEW means it cannot count as finally approved either. The delivery report lists every item, not only those done.

"Applies to" column: All = every output; Video = only where there is picture (audio-only records "N/A"); Episode / Short clip = only that kind. Use a program to measure whatever a program can measure.

## A. Source and timing

| # | Check | Applies to |
| --- | --- | --- |
| 1 | Right source: full episode from original material; clips from the approved release version (with required deletions applied); the source record notes how it was recorded and its quality | All |
| 2 | Time map recorded as source in, source out, output start and overlap, with one table for audio and video | All |
| 3 | Total audio and video duration differ by ≤1 frame | Video |
| 4 | Every audio processing pass covers the whole piece (head, tail, both sides of joins), measured in segments | All |
| 5 | Audio–video sync measured on its own (original audio vs original picture from the same camera) | Video |
| 6 | No must-delete range made it into the output (check the source mapping, and re-transcribe and search the final output, including synonyms and transcription variants) | All |

## B. Cut points and technical joins

| # | Check | Applies to |
| --- | --- | --- |
| 7 | Ordinary cuts: every cut lands in silence (measured against the source, including the start of the first sentence and end of the last), no final words chopped | All |
| 8 | Micro-cuts: every cut has had technical join checks; listened to cut by cut or spot-checked as agreed, with the notes stating how many cuts in total and how many were actually listened to | All |
| 9 | No clicks or high-frequency jumps at joins; no sudden level jump across them; natural gap rhythm | All |
| 10 | Differences found by re-transcribing joins have each been listened to (transcription is only a lead) | All |
| 11 | Silence-only steps: deleted ranges have been level-screened (a lead only), and those that failed have been listened to | Only operations claiming to remove only silence |
| 12 | Unnecessary long pauses within the same topic have been shortened; reasons noted for the ones kept | All |
| 13 | Camera matches speaker (checked against which track is producing sound) | Video |
| 14 | Peak, loudness and silence detection; silences are first judged for whether they serve the content | All |
| 15 | Black-frame detection | Video |
| 16 | Level difference between speakers within the working threshold (using only single-speaker seconds) | Multiple speakers |

## C. Semantics

| # | Check | Applies to |
| --- | --- | --- |
| 17 | Edit points: after every edit, check question–answer pairing, references, premises, speaker attribution, original meaning | All |
| 18 | Whole-piece reference scan: every referring and connecting word in the output transcript is confirmed to still have its referent | All |
| 19 | Full read-through: read a transcript matching the actual output and check the storyline from start to finish | All |
| 20 | Opening is the start of a sentence, the middle stands on its own, the ending is complete; into the topic within five seconds | Short clip |
| 21 | Stutters, filler words and host repetition handled per the rules; notes state how many were found, how many cut, how many left because of risk | All |

## D. Subtitles and text

| # | Check | Applies to |
| --- | --- | --- |
| 22 | Subtitles checked against the audio sentence by sentence | With subtitles |
| 23 | Subtitles read through for meaning (homophone errors, pronoun errors (he/she), missing or extra characters) | With subtitles |
| 24 | Natural breaks, punctuation, follows the audio (if using the single-line practice: one line at a time) | With subtitles |
| 25 | At least one independent check listening only to the output audio, with each difference listened to | Short clip (recommended for episodes) |
| 26 | Ranges marked "silence" in the transcript but with significant level have been listened to, and missed words added | Where a transcript is used for word-by-word trimming |
| 27 | Chapter titles, name tags and on-screen text match the actual content and don't reveal deleted content | All (name tags and on-screen text video only) |

## E. Packaging

| # | Check | Applies to |
| --- | --- | --- |
| 28 | Hooks: each understandable on its own, pauses match the actual gaps, pauses are not digital silence | Where there are hooks |
| 29 | Chapters: start at the beginning of a question, strictly increasing, first and last aligned with the main content | Where there are chapters |
| 30 | Progress bar checked by frame sampling | Video with a progress bar |
| 31 | Music: intro and outro entry and exit points, intro and outro not the same track (if using that practice), transitions only at big topic jumps, licence records present | Where there is music |
| 32 | Watermark (if used): applied only once, master has no watermark | Video with a watermark |
| 33 | Vertical safe area: subtitles, name tags and key picture within the safe area; cover frame count based on the real frame rate | Vertical video |

## F. Delivery

| # | Check | Applies to |
| --- | --- | --- |
| 34 | Only one path for the delivered file; old versions archived; file name includes version and time | All |
| 35 | Compared with the previous version; confirmed items unchanged, or changed with a reason and sent for re-confirmation | All |
| 36 | Processing that doesn't change content (transcoding, resolution change): final output checked against the time map, compared with tolerance if lossy, anomalous ranges reviewed | Where applicable |
| 37 | Delivery notes state whether it was independently reviewed | All |
| 38 | Explicit approval obtained from the approver as agreed in advance (silence doesn't count) | All |

## Maintenance

Maintain the checklist independently, adding items as you hit new problems, each with an actionable check method and its applicability.
